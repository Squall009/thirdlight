## 1. Scope

`packages/editor` gains the packet-28 authoring path:

- pure, Node-testable modules:
  - `session/property-controls.ts` — the schema-driven control model for the
    seven-type declared-property vocabulary (typed default, constraints,
    bounded value errors), input parsing for invalid numeric/reference input,
    the one `setBehaviorProperties` command builder (whole values map), and the
    read-only `collider`/`controller` contract-shape controls;
  - `session/prefab-authoring.ts` — capture preflight + `createPrefab` planning,
    `instantiatePrefab` planning (root parent + root transform + declared
    overrides only), override-draft collection, and the client recovery for a
    stale revision / backend-rejected instance limit;
  - `session/prefab-projection.ts` — the definition + published-declaration
    projection, advanced by the same `mutation.applied` records (copies are not
    links: definition/declaration changes never rewrite an instance);
  - additive `setBehaviorProperties` convergence + prefab/component fields in
    `session/projection.ts`;
- transport additions in `session/client.ts` (bounded `queryPrefabs` /
  `queryBehaviors`, definition/declaration hydration on every full resync, the
  `limits_exceeded` `limit`/`current`/`max` detail preserved on the failure
  path);
- the React `ui/PrefabPanel.tsx` (Create Prefab Definition / Place Copy /
  initial declared-property override) and the extended `ui/Inspector.tsx` +
  `ui/PropertyControls.tsx` (declared-property controls, copy provenance label,
  read-only physics-component controls), wired in `ui/App.tsx`.

No accepted contract, fixture, lockfile, `node_modules`, backend, workspace,
commands, protocol or three-adapter source was changed. The new editor
`package.json` exports are additive subpaths for the pure modules.

## 6. Limitations / contract-change requests

- **C28-1 (collider/controller editing).** The accepted M2 command set has no
  operation that creates or edits `components.collider` or
  `components.controller`: `setComponent` owns only `box`/`camera`/`model`
  (commands.md §8.10) and M2 has no component add/remove (its own non-goal
  text). The packet-28 requirement "collider/controller component controls" is
  therefore met as **read-only contract-shape controls** derived from
  project-model §10.7/§10.8/§21, each labelled with the reason and the request
  id; no fabricated command and no direct state write (same discipline as
  C27-1). Proposed minimal diff: extend commands.md §3.1.6/§8.10 with
  `component ∈ {collider, controller}` (`COMPONENT_FIELDS.collider = ['shape']`,
  `controller` marker with an empty field set) plus an explicit
  component-add-at-creation rule; until accepted the controls stay read-only.

  **Repair note (GG-2, 2026-09-19):** C28-1 is closed. `commands.md`
  §2/§3.1.6/§5.3/§8.10/§9.1 now accept `component ∈ {collider, controller}`
  with add/edit/remove; `session/property-controls.ts` builds real
  `setComponent` args and the Inspector renders editable controls. The
  read-only paragraph above is retained as the pre-repair record.
- **Reopen wording (GG-5).** The reopen claim above is hydration from the same
  query-result JSON; `client.fullResync()`'s new query reads are
  browser-transport code exercised only by the packet-37 procedure, not by a
  Node test.
- **Limitation (prefab bytes bound).** The capture preflight enforces
  `prefab_entities`/`prefab_depth`/`prefabs` but not `prefab_bytes`
  (project-model §20.3): the editor has only type-level access to
  `project-model`, so it cannot call the model's canonical writer to measure
  the canonical definition bytes. The backend remains authoritative for that
  bound (its `limits_exceeded` surfaces through the same recovery path).
- **Additive failure detail.** The pure `MutationResponse` (packet 10) now
  carries the optional `limits_exceeded` `limit`/`current`/`max` fields so the
  UI can name the exact rejected bound; no existing field or semantics changed.
- `fullResync()` now issues two additional bounded reads (`queryPrefabs` with
  `includeEntities`, `queryBehaviors` with `includeDeclaration`) so a reopen
  rebuilds definitions/declarations from queries — the packet-27 asset query is
  unchanged.
