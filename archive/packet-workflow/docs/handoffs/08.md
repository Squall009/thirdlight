## What was built

Two new workspace packages per `docs/contracts/runtime.md`,
`docs/contracts/project-model.md` §12/§15 and `docs/contracts/dependencies.md` §3/§4:

- **`@thirdlight/runtime`** (`packages/runtime`, three-free, I/O-free):
  - `snapshot.ts` — `validateRuntimeSnapshot`: strict wrapper shape
    (`snapshotId == <projectId>@r<revision>`, `scene` deep-validated by the
    `validateScene` re-validation path), reasons `wrapper`/`scene`/
    `revision_mismatch`/`id_mismatch`; returns an isolated deep clone (deep-freeze
    the input and it survives a full run unchanged).
  - `runtime.ts` — `instantiateRuntime` + `RuntimeInstance`: state machine
    (`instantiated/running/stopped/disposed`), single loop owner (rAF driver by
    default in browsers, manual `tick(nowSeconds)` driver for tests/CI; a
    `clock() => seconds` function is always the time source), wall→sim anchor on
    first frame, fixed-step 120 Hz default (configurable `fixedStepHz` 1..1000),
    `MAX_CATCHUP_STEPS = 8` with `droppedSteps` + anchor resync (§5.4),
    per-step module isolation (§5.1: backup/restore `curr` on throw; the failed
    module instance is not re-created), 32-entry error ring + cumulative
    `errorCount`, all messages ≤ 256 chars.
  - `interp.ts` — lerp + slerp (sign-aligned, nlerp shortcut at ~0),
    `alpha = (simTime − stepIndex/dt)/dt`; `getInterpolatedState()`.
  - `demo.ts` — built-in moving-box demonstration (§7.1):
    `x = x0 + 0.5·sin(2π(stepIndex+1)/480)`, period 4 s at 120 Hz.
  - `registry.ts` — branded registry; name syntax
    `^thirdlight\.[a-z0-9]+:[a-z0-9-]+$`; `BUILTIN_MODULES`.
  - `diagnostics.ts` surface in `getDiagnostics()` (§8: `state`, `stepIndex`,
    `simTime`, `droppedSteps`, `errorCount`, `errors[]`).
- **`@thirdlight/three-adapter`** (`packages/three-adapter`, edges: runtime
  types-only + three): `createSceneAdapter` never throws (structured errors),
  lazy WebGL (renderer created on first render attempt), scene sync
  (transforms/box mesh + Lambert material + directional/ambient lights), camera
  (exactly one, perspective), `renderFrame()`, `captureScreenshot(maxWidth=1024)`
  (clamped to 2048; structured `screenshot_failed` otherwise), `diagnostics()`
  (`renderBackend: null` in non-browser absence, renderer name/isWebGL2
  otherwise), idempotent `dispose()` (`alreadyDisposed: true`) with
  `forceContextLoss()`.

## Interpretation decisions (recorded for review; none changes contract meaning)

1. **Step ordinal:** a module's `step(state, stepIndex)` receives the 1-based
   ordinal of the step being executed (m1-acceptance exact points pin this:
   x0+A at state stepIndex 119). The `SimState` view still carries the §4/§5.3
   pre-increment state fields.
2. **Error recording:** the module is invoked every step; each failed attempt
   records one `module_error` (this makes the m1-acceptance 33-recorded-failures
   ⇒ 32-kept ring check runnable). On failure the step is a no-op (state frozen,
   no step advance, no `create` retry); per-frame attempts stay bounded by
   `MAX_CATCHUP_STEPS` because the frozen `simTime` makes rawN grow.
3. **Capped frames:** after the drop-resync, `alpha = 0` for that frame.
4. **Adapter absence values:** `diagnostics.renderBackend === null` in
   non-browser environments; the adapter `ERROR_CODES` set is this packet's
   definition (canvas_invalid, render_unsupported, render_failed,
   screenshot_failed, adapter_disposed).
