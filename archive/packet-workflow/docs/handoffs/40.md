## Outcome

`gameplay.md` is the proposed **new contract home** for the M3 session: the run
state machine (`awaitingStart → playing → respawning → playing`,
`playing → won`, `replay`, terminal runtime failure ≠ death; stop/dispose from
every state), the queue/boundary visibility rules, the exact respawn delay
(`RESPAWN_DELAY_STEPS = 30`, no wall clock), the M3-only schedule
(`boundary → sample → intent → controller → physics → transform → gameplay →
camera → commit`), the pure swept upright-capsule vs axis-aligned XY zone
predicate over the **last completed motion segment**, same-step precedence
(death > checkpoint > goal; ascending `entityId` ties), the runtime-owned reset
transaction `R1–R8` with a coherence table, the committed read-only `GameView`,
the camera math (dead zone, bounded fixed-step smoothing, authored bounds,
frustum clamp, hard snap, presentation-only resize, one writer), and the finite
limits and five new error codes. `diffs/runtime.md` gives the exact `OLD → NEW`
edits (`R40-1…R40-16`) to `runtime.md`, incl. new §15. Key pins: the boundary
runs **before** `prev := curr`, so a reset makes `prev == curr` — one fact that
removes both the teleport sweep and the render streak; the gameplay phase must
use the runtime-provided `lastMotionSegment`, because during step `n` the commit
order leaves `state.prev` at the end of step `n−2`; a first-live-step jump gate
plus neutral delay frames prevent a held/tapped jump through start/respawn;
`PhysicsPort.reset` stays diagnostics-only.
