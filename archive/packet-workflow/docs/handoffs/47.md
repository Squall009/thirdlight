# Packet 47 — WAV and version-bound animation import inspection

## Outcome

`@thirdlight/asset-pipeline` now exposes two pure leaf inspectors over supplied
bytes, and the promoted `pcm-wav` rules are real in `@thirdlight/project-model`:

- **`inspectAudio(bytes, options)`** (`src/inspect-audio.ts`): the 12 ordered
  stages of `presentation.md` §41.4.4 with the exact §41.4.1 header/chunk bytes,
  the §41.4.2 arithmetic, the `pcm-wav` recipe (`recipeVersion: 1`,
  `toolchain: { "asset-pipeline": "0.1.0" }`, **no `extensions` key**) and
  `PcmWavMetrics` in its exact key order. Rejection is bytes-only: no
  extension/MIME/`kind` input, no URL/`data:`/compressed form. No I/O, Node
  built-in, decoder, `three`, network, cache write, asset-ID decision or state
  mutation; cancellation/timeout uses the accepted injected `ImportJobPort` and
  reports `asset_timeout` (nothing invented). New `ImportDiagnosticCode`s:
  the nine §41.7.2 C audio codes; new `ImportLimitName`s: `audio_pcm_bytes` plus
  the four §41.3.3 animation caps.
- **Role-aware GLB proposal**: `ImportOptions.animation.roles` requests the
  animated profile. Stages 3–6 of §41.3.2 run against the proposal's real clip
  list, then A1–A6 in order (clips ≤ 8; no `skins`/`JOINTS_0`/`WEIGHTS_0`;
  channels ≤ 64 total and ≤ 32 per clip; sampler input keyframes ≤ 4096;
  longest clip ≤ 10 000 ms; no scene-root `translation` channel), carrying the
  documented §41.7.2 A fields (`role`, `clipIndex`, `clips`, `roles`, `matches`,
  `nodeIndex`, `nodeName`). Without `animation` the accepted M2 proposal and its
  `gltf-glb` recipe are byte-unchanged.
- **Digests**: `importRecipeDigest` now accepts the audio recipe and
  `importMetadataDigest` the audio proposal; both keep the one canonical-JSON
  rule (`commands.md` §6.6 rule 2). The audio `recipeDigest` equals
  `SHA-256(canonical JSON of importRecipe)`.
- **CC-44-2**: `content.ts`'s audio branch enforces §18.5/§18.6/§41.4.3 on load
  (exact `pcm-wav` recipe with `extensions` absent; exact `PcmWavMetrics` keys;
  `sourceByteLength === 44 + pcmBytes`; every §41.4.2 cap and derived value;
  `limits_exceeded`/`field_value`; never normalized) with the audio types in
  `types-v3.ts` (`GltfGlbRecipeV3`/`PcmWavRecipe`/`ImportRecipeV3` union,
  `PcmWavMetrics`, `AssetMetricsV3`) and kind-aware v3 canonicalization. The
  three packet-39 placeholder audio records were regenerated from the real
  236-byte `source-preimages/cue-start.wav` (96 frames, `pcmBytes` 192,
  `durationMs` 2, `riffChunkBytes` 228) with `index.json` digests/bytes/notes.
- **CC-44-5**: `errors.ts` gains exactly the six §41.7.2 A codes and the six
  §41.7.1 limit names (`ERROR_CODES` +6, `LimitName` +6); nothing else.
- **Fixtures**: `fixtures/m3/media/**` grew from 40 to **65** self-generated
  files (16 GLBs incl. the A1–A6 boundary positives `clips-at-cap` /
  `tracks-at-cap` / `keyframes-at-cap` / `clip-10s` and the `bad-joints` /
  `bad-skin-root` / `many-keyframes` / `many-tracks-per-clip` negatives; the
  full §41.4.4 stage/boundary WAV negatives incl. `fact`/`bext`/`cue `/`smpl`/
  duplicate chunks, RF64/BW64, µ-law/A-law, the exact 196 608-byte source bound,
  non-WAV bytes, `data:`/URL and gzip; `cue-min` 1 frame, `cue-preimage` 236 B;
  a `wav-cases.json` `audioRecord` anchor). The media checker re-derives the
  recipe/`recipeDigest`/`metadataDigest` from the bytes, cross-checks the three
  contracts audio records and their index digests, and gained a
  `--corrupt-control` mode (9/9 detected).

## Limitations / contract-change requests

- **CC-47-1 (scope exception).** `fixtures/m3/contracts/envelope/invalid/
  cue-kind-mismatch.json` also carried a packet-41 placeholder audio record;
  the promoted rules made it invalid for the wrong reason, so the bounded
  CC-44-2 repair had to include it (+ its `index.json` entry). Proposed: the
  promotion/CC-44-2 text should name every stale placeholder fixture.
- **CC-47-2 (scope exception).** `packages/commands/src/m3-commands.test.ts`
  created the audio record from placeholder constants; enforcing CC-44-2 makes
  the command gate refuse it. The two constants were brought to the promoted
  shape and the model-reimport metrics split out — no assertion weakened.
- **CC-47-3 (scope exception).** The packet-39 checker's metric key-order rule
  assumed every `metrics` member is the 13 GLB fields (pre-§18.6); it is now
  `kind`-aware. Both lists remain exact for their profile.
- **CC-47-4 (reading).** §41.7.2 C lists only the audio additions to
  `ImportDiagnosticCode`, but stages 5–6 and A1–A6 must be reportable by the
  pipeline, so the six §41.7.2 A codes were added too; stages 1–2 stay
  model-owned (a structurally malformed request is a `TypeError` at the
  pipeline boundary). Proposed: state the pipeline's copy of A in §41.7.3.
- **CC-47-5 (open gap).** §41.4.5's `AUDIO_MAX_REFERENCED_CUES = 6`
  (`limits_exceeded` `audio_cues`) is now in the closed limit set but is **not
  enforced** by any layer: counting distinct referenced audio assets spans
  `content.game` + scene checkpoint activations (cross-block), outside packet
  47's allowed writes. Proposed: add the count to `project-model`'s cross-block
  composition or the command layer.
- **Publication wiring is 48.** The command/workspace `publishAsset` path does
  not yet call the role-aware proposal, so §41.3.2 stages 5–7 remain unreachable
  through a real publication in this tree (packet 45 recorded the same; the call
  site is `packages/commands`, outside packet 47's writes). The pipeline side is
  complete and is exercised directly by the integration suite.
- **CC-45 residuals touching media:** CC-45-7 (`modelAnimation.version` on
  reimport) and the media envelope's `modelAnimation` role placeholders are
  unchanged/unfixed here (packet 41/45 text); the runtime `setRoles` re-check,
  `animation_role_unresolved`, the session loader and the WS/MCP path are 48/53.
