# Packet 56 — Gameplay and camera authoring controls

**Outcome:** the complete gameplay layout is now authorable without raw JSON.
The editor gained a **Gameplay panel** (Game / Zones / Camera / Settings tabs)
plus the imperative viewport zone overlay; every mutation goes through the
accepted command path (the backend projection stays authoritative —
sessions.md §6; authoring.md §A8 rows 1–4/6–10/12/19). Zone gestures follow
the packet surface rule: **zero commands during the gesture, one on release,
none on cancel, one undo** (the pure `ZoneGesture` owns the decision; the
overlay is pointer routing + preview only).

## What was built

- **`session/gameplay.ts`** (new, pure): the six-key settings registry mirror
  (commands.md §8.11 bounds + the slide≤climb cross-rule),
  `parseSettingsDraft`/`planSetSettings` (touched keys only); the
  game-config form parse (string bounds 64/160/320, ID syntax, finite level
  numbers, `minX<maxX`, `minY<maxY`, `killY<maxY`), the reference preflight
  (exactly-one controller / camera+cameraFollow / spawn / ≥1 goal / ≤1
  checkpoint), `planSetGameConfig` (create = the complete canonical block
  with null cues; edit = changed top-level fields only — `cues` is never
  touched, packet 57 owns it), `planCreateZone`/`planEditZone` (the §23.3.1
  bounds; the checkpoint field rules; the **two-step remove-then-re-add**
  for a checkpoint role switch — a single merge edit cannot drop the
  checkpoint fields), `parseCameraFollowForm`/`planSetCameraFollow`
  (add = complete value, edit = changed fields).
- **`session/zone-gesture.ts`** (new, pure): move/resize/create gestures;
  `commandDecisions` 0/1/0; the bounded `revision_conflict` rebase (≤1, move
  re-applies the delta to the re-read base; resize/create surface the
  conflict); a negligible create drag places the role default at the anchor;
  an unplannable checkpoint create decides nothing.
- **`viewport/zone-overlay.ts`** (new, imperative three.js, framework-free):
  role-colored zone rectangles + border on z=0, spawn cone markers, the
  cameraFollow bounds line, the selected zone's SE resize handle, the in-flight
  preview mesh; pointer routing (tool → create; handle → resize; body → move;
  else the orbit/pick path runs); every pointer position is reported as a
  game-plane world hit (ray ∩ z=0).
- **`viewport/viewport.ts`**: the overlay is consulted FIRST on pointer down
  (a consumed down drives a zone gesture and skips orbit/pick), frames/end feed
  the App, selection drives the handle, `setZoneTool` / `previewZonePose` /
  `cancelGesture` (zone gesture takes precedence over the gizmo gesture).
- **`ui/GameplayPanel.tsx`** (new): the four tabs. Zones: list rows (role,
  size, checkpoint safe-spawn picker, Save/Delete) + Add at origin +
  "Place in viewport" (arms the tool; disabled for a checkpoint without a
  selected safe spawn); spawn list with Add/Place; the ≤1-checkpoint warning.
  Camera: entity picker + dead zone/smoothing/bounds. Settings: six bounded
  fields; only touched keys are submitted. Backend errors are shown at the top
  of the active tab and never lost.
- **`session/projection.ts` + `session/client.ts`**: v3 components
  (`gameZone` / `playerSpawn` / `cameraFollow`) hydrate from the full state and
  converge from `setComponent` change records (add/edit/remove via null); the
  client tracks the `content.game` block (from `queryGameConfig` on every full
  resync — reopen retains the authored configuration — and from applied
  `setGameConfig` change records) and the settings map (from applied
  `setSettings` changes); `setGameConfig` / `applySurfacePreset` changes
  advance the projection without a gap. New command wrappers
  (`setGameConfig`, `setSettings`, `setComponent`, `createGameEntity`,
  `deleteEntityCommand`) over the ordinary envelope path (original `requestId`,
  bounded retry, dedupe).
- **`ui/App.tsx`**: the gesture driver (base pose captured from the projection
  at gesture start; the single commit command issued at the gesture's
  expected revision with the bounded rebase; the spawn tool rides the create
  gesture for position but creates a `playerSpawn` marker, not a zone), Esc
  (cancels the gesture, else clears the armed tool), the panel wiring.
- **`editor.css`**: the panel styles. **`tests/browser/m3-authoring/`**: the
  manual real-backend browser procedure (Z1–Z11 checklist) — UNVERIFIED here
  (no browser; packet 38 baseline §1).

## Acceptance criteria (packet 56)

- **PASS (Node-verified)**: invalid references/coordinates are refused by the
  preflight before any command (parse + reference tests); duplicate roles /
  illegal deletes are the backend's structured errors shown by the panel
  (backend rejection tests from 44/45; the panel renders the error verbatim);
  the stale-edit-during-gesture failure mode is the bounded rebase (gesture
  tests: one rebase, a second conflict surfaced, not retried);
  disconnect/resync + lost-ack retry is the client's existing establish
  resync (now re-reading `queryGameConfig`) + envelope bounded retry/dedupe;
  one-undo-per-gesture (exactly one command decided).
- **PASS**: reopen retains the authored game configuration — `fullResync`
  re-queries `queryGameConfig` on every full state.
- **UNVERIFIED (no browser in the container)**: the real-backend browser
  authoring + SDK-edit convergence walk (Z1–Z11 in
  `tests/browser/m3-authoring/README.md`), the rendered overlay, and every
  pixel/pointer statement. The evidence list is the README's table.

## Limitations

- **No accepted query returns settings VALUES** (`queryProject` carries the
  `settingsKeys` count only). The Settings tab seeds from the registry
  defaults, tracks the map from applied `setSettings` changes (full
  `previous`/`next` per §5.3), and submits only touched keys. Documented in
  the panel UI; flagged for the M3 acceptance record (not a CC — the contract
  is binding; the panel degrades safely).
- Cue assignment (game-config `cues.*`) and the checkpoint activation
  appearance are packet 57's surface: 56 creates the block with null cues and
  the default activation; the 57 pickers fill them via partial edits.
- Zone `activation` edits, surface presets, lighting — 57.
