## What was built

### `@thirdlight/protocol` (`packages/protocol`) — pure, I/O-free, no Node
builtins, no DOM. Edges to `project-model`/`commands` are **types-only**
(dependencies.md §4.1). Single home of wire shapes (sessions.md §3/§4/§5/§7/§11/§13):

- `ids.ts` — ID syntax constants + validators: `sess-/conn-/play-/relay-`
  + 32 hex; `req-` + 32 hex; `wsToken` 64 lowercase hex.
- `strict.ts` — strict JSON payload discipline (sessions.md §1/§6.1/§11.2):
  `parseStrictJsonBytes` enforces the project-model §12.3 pass-1 rules
  **itself** (BOM-free UTF-8 → strict RFC 8259 syntax → no duplicate keys →
  no trailing garbage), mapping failures to `invalid_request`; plus the shape
  helpers `checkShape` / `checkField` / `checkOptionalObject`
  (`field_missing`/`field_unexpected`/`field_type`/`field_value` with JSON
  Pointer `path`). The parser is self-contained because a value import of
  `project-model.parseDocumentBytes` would violate the types-only edge.
- `errors.ts` — `SessionError` shape + code set + `statusFor` (§11.2 mapping,
  with the `unauthorized`→401 and `bad_origin`/`session_required`→403
  exceptions) + `clipMessage` (≤ 256).
- `ws-events.ts` — the exhaustive §7 inbound-event catalog:
  `parseInboundEvent` (unknown `type` ⇒ survivable `unknown_event`; malformed
  ⇒ `protocol_error`), event builders (`makeAttached`, `makePong`,
  `makeErrorEvent`, `makePlayStarted`, `makeScreenshotRequest`,
  `makeDiagnosticsRequest`), and the frame-bound helpers (default 64 KiB;
  `screenshot.ack` 1.5 MiB; outbound 1 MiB). The `screenshot.ack` /
  `play.diagnostics.ack` validators carry the payload fields
  (`dataUrl/width/height`, `diagnostics`) through to the caller.
- `http.ts` — HTTP payload validators (strict): `parseEstablishRequest`,
  `parsePlayStartRequest`, `parseScreenshotRequest`,
  `parseAdminCreateProjectRequest`, `parseAdminNoArgsBody`,
  `parseCommandEnvelope` (the 5 mutation ops + 3 query ops; `isMutationOp`).
- `bridge.ts` — the exhaustive §13.5 bridge allowlist + validators
  (`validateBridgeEditorToPreview`, `validateBridgePreviewToEditor`): `v: 1`
  discriminator, exact type sets, the `tl.handshake` nonce echoed by
  `tl.handshake.ack`, `tl.screenshot.result` (ok ⇒ dataUrl+width+height),
  `tl.diagnostics.result` (≤ 16 KiB). (Editor/preview postMessage wiring is
  packet 10.)
- `index.ts` — public surface.

### `@thirdlight/backend` (`packages/backend`) — the HTTP/WS server + the
`/services` application-services surface. Edges: `protocol`, `workspace`,
`project-model` (types only), `ws`; Node builtins `http`, `fs`, `path`,
`crypto` only. Uses local ambient declarations (`ambient.d.ts`) because
`@types/node`/`@types/ws` are not approved; no `Buffer` (DOM `lib` is in the
base tsconfig) — `TextEncoder`/`TextDecoder` + a `toHex` helper.

- `config.ts` — `parseBackendConfig` (strict; rejects wildcard origins, bad
  binds, non-exact tokens), `mergeTimeouts` (test-only seam over the §11.5
  production constants).
- `sessions.ts` — `SessionRegistry`: one active authoring session per project
  (§5.1); single-use/TTL `(sessionId, connId)`-bound `wsToken`s (§4.3);
  128-entry bounded session log (§11.1); protocol-error window (§5.2).
  Re-attach keeps the old socket bound until the new upgrade replaces it so
  the server can close it (1000 `detached`); a replaced socket's detach does
  **not** count as an owner loss.
- `play.ts` — `PlayManager`: the §10 state machine
  (`active → presented → stopping → stopped`; terminations
  `preview_failed`/`preview_timeout`/`expired`/`session_lost`), frozen play
  revision/snapshotId, the present/inactivity/stop-ack/relay timers, and the
  §12 screenshot/diagnostics relay (relayId-routed acks; `relay_failed`
  carries `cause`).
- `backend.ts` — `createBackend`: two listeners (authoring + separate-origin
  preview), auth/origin policy (§4), the routes:
  - `POST/GET /api/v1/sessions`, `GET /sessions/:sid/log` (§5.1/§11.4)
  - `POST /api/v1/projects/:projectId/commands` (§6.1: strict bytes first,
    then the commands.md pipeline; mutation ⇒ `runCommand` + `mutation.applied`;
    query ⇒ workspace query path; caller binding `session_required`; response
    is exactly the commands.md result, so `revision_conflict` carries
    `currentRevision`)
  - `POST /projects/:pid/play` + `/:playId/stop|screenshot|diagnostics`
    (§10/§12; the explicit registered-connected-session requirement for live
    actions)
  - `POST /api/v1/admin/projects` + `/:pid/release|takeover|accept-external|
    discard-external` (§6.3; admin-scoped; delegated to the workspace)
  - `/api/v1/ws` upgrade (§4.3 token verify; §5.2 frame bounds + protocol-error
    tolerance; `attached { connId, revision }`; one-shot `play.started`
    delivery on re-attach §7.1)
  - static serving (authoring bundle + preview template `injects exactly
    { v, authoringOrigin }` + the static script; no credentials, no `/api/`);
    path traversal containment (normalize + containment + realpath re-check).
  **Delegation, normatively:** every persistent change goes through the
  workspace service (`runCommand` is the sole executor); the transport never
  mutates files. No headless browser hosting, no server GPU assumption.
- `services/index.ts` — the `/services` surface (packet 11's edge):
  `createBackend`, config parsing, `PlayManager`, constants.
- `index.ts` — the executable bootstrap (not imported by any package).

## Interpretation decisions (recorded per AGENTS.md)

1. **Query envelopes carry no `requestId`** (commands.md §4: query request is
   `{ op, projectId, args? }`); the workspace strict validator rejects a
   `requestId` on a query as an unknown field. The protocol pre-check
   (`parseCommandEnvelope`) stays permissive about an optional `requestId`
   (mutations need it); the query shape is enforced by the workspace.
2. **`/commands` responses pass the raw commands.md error through** (sessions.md
   §6.1 "exactly the commands.md result") — a `SessionError` re-wrap would
   drop `currentRevision`/`expectedRevision` (commands.md §6.4 requires
   `revision_conflict` to always carry `currentRevision`).
3. **Explicit `stop` requires a connected owner WS**; automatic terminations
   (`preview_failed`/`preview_timeout`/`expired`/`session_lost`) proceed even
   when the owner is detached, marking `stopUnconfirmed: true` when there is no
   ack path (sessions.md §10.3).
4. **`relay_failed` cause travels under `cause`** (the §11.3 row lists the
   carried field as `code?`; top-level `code` is fixed to `relay_failed` by the
   same row + §7.2, so the cause rides under `cause`).
5. **`snapshotId = <projectId>@r<revision>`** (project-model §15), composed by
   the backend from the current authoring revision at play start; frozen on the
   play record.
6. **Fresh projects are the project-model §15 default scene** (one `cam-main`
   camera at revision 0), not an empty scene.
7. **HTTP body > 1 MiB ⇒ `invalid_request` (400)** — `payload_too_large` is not
   in the session error-code set.
8. **`startBackend`/tests use a shortened-timeout seam** (`mergeTimeouts`) over
   the §11.5 production constants; production uses `DEFAULT_TIMEOUTS`.
