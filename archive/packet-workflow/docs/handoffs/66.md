## Contract of record (`planning/m4-contracts/distribution.md`)

- **The kit** (§1–§3): a local, integrity-indexed distribution of the
  EXISTING workspace — a closed allowlist (root manifests + exact lockfile
  bytes, the 17 units' source, the 4 tooling scripts + tests, the 9 contract
  files, the M4 template set, plus 2 generated data files: `kit.json` +
  `NOTICE`). Never in a kit (negative inventory): `node_modules/`, `dist/`,
  `.git/`, `fixtures/`, `samples/`, top-level `tests/`, project data,
  symlinks. The identity is **digests,
  never a fabricated release tag/version** (m4-plan §2.3): `engineRef` is
  `working-tree` (this dirty baseline — a commit alone cannot identify it)
  or `commit` (supplementary, digests always present); `kitDigest` = the
  block digest over the allowlisted source files (the generated data embeds
  the digest, so it is inventoried but not a digest input). `engineVersion`
  stays `0.1.0`.
- **Install** (§4): `node_modules` is machine-dependent (25
  `@esbuild/<platform>` binary packages) and never vendored — install is
  `npm ci --prefix <kit>` (lockfile-authoritative ⇒ a **transitive floating
  dependency is impossible by construction**; registry unavailability is the
  structured `kit_install_unavailable`, never a silent skip).
- **C12 boundary** (§5): the exact build-only-vs-runtime table — browser
  runtime: three/react/react-dom/rapier (editor-only React rule holds in
  the kit); node runtime: ws (backend bundle), MCP SDK (mcp bundle);
  **esbuild 0.28.2 = build-only-at-runtime** (an `exporter`/`behavior-build`
  dependency, never a browser-bundle member, EXTERNAL in the backend
  bundle); typescript/vitest dev/test-only. Normalized graph paths = the
  accepted §4.2 sets (+ the C64-6 `./gltf-loader` subpath rows).
- **Game layout + pin** (§2): the game owns `game.json` (gameId, projectId,
  template provenance, `enginePin` = engineVersion+kitDigest+lockfileDigest,
  the documented build entry); the vendored kit is immutable (re-hashed
  before every build: `kit_tampered`/`kit_lockfile_mismatch`/
  `kit_inventory_missing`); upgrade = an explicit second-kit + re-pin
  procedure.
- **The public Node build tool** (§6): `tools/game-build.mjs` (plain
  `node:*` — no new dependency) — 8 ordered steps: resolve paths from its
  own file location (never `process.cwd()` — the engine's cwd-rooted
  `build.mjs` runs only via `npm run build`, where npm fixes the cwd) →
  verify kit → verify pin → `npm ci` → `npm run build` (the accepted
  check-deps→check-boundaries→typecheck→build pipeline) → verified template
  install → export through the **accepted public admin export route** (kit
  backend spawn with `THIRDLIGHT_ENGINE_ROOT=<kit>`) → verify the static
  closure. No absolute checkout path, no symlink escape, no secrets on disk.
- **Licenses** (§8): `UNLICENSED`/private engine source ⇒ the kit is for the
  owner's local use; **no license grant, no public publishing**; the NOTICE
  (required — absence = `kit_notice_missing`) records the per-entry lockfile
  license names (extracted, never asserted beyond the manifests) + the
  self-generated content license.
- **Owned diffs (Gate Q):** C66-1 dependencies (the kit = a distribution of
  the existing workspace; the game-build tool is a NEW **tooling unit edge**
  recorded for Q — CCR-66-2; no package/dep/pin/lockfile change), C66-2
  export (no change — the build entry is the accepted admin export route;
  the kit satisfies `THIRDLIGHT_ENGINE_ROOT` by shape; scans unchanged),
  C66-3 workspace (no change — the game's project is a plain workspace
  instance under the game's data root; the 65 template operator runs
  against the kit's `templates/` set; no new artifact class).
