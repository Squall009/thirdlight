## What was implemented

All changes are inside `packages/three-adapter/**` + the packet's browser

**New `src/lighting.ts`** — the pure realization math (no three.js, no DOM,
no Node built-ins, no clock; the adapter maps plans onto THREE objects):

- `SHADOW_PROFILE` — the seven §41.1.2 frozen constants (512 /
  `PCFShadowMap` / 0.5 / 20 / 2 / 64 / 200), deep-frozen, bit-equal to the
  promoted fixture's `shadow` block (pinned in `lighting.test.ts`).
- `deriveShadowCamera(level, direction)` — the exact §41.1.3 derivation:
  centre `((minX+maxX)/2, (minY+maxY)/2, 0)`, `halfExtent = max(Δx/2, Δy/2)
  + margin`, `far = min(distance + halfExtent + margin, farMax)`,
  `lightPosition = centre − n·distance` (a derived normalized **copy** of the
  authored direction — the document is never rewritten), the orthographic
  shadow camera, and the `withinBounds` flag (`halfExtent ≤ 64`). `-0` is
  canonicalized to `+0`.
- `decideShadows({webgl2, castShadow, probeOk, level, direction})` — the
  §41.1.4 decision in the exact priority the promoted fixture's reference
  re-derivation uses: no WebGL 2 ⇒ hard `render_unsupported` (unplayable);
  author `castShadow: false` ⇒ `off`/`cast_shadow_false`; probe failure ⇒
  `off`/`shadow_unsupported` (soft: key light only); bounds exceeded ⇒
  `off`/`shadow_bounds_exceeded`; else `on` + the plan. The plan is present
  on every `ok` outcome — §41.1.2 rule 2 derives the directional position/
  target regardless of shadow state.
- `SURFACE_PRESETS` — the three §41.2.1 frozen rows (value rows, never
  resources). `three-adapter` has no `project-model` edge (dependencies.md
  §4.1), so it keeps its own copy — single change point per package; the
  test pins it bit-equal to the contract rows and the media checker pins the
  promoted fixture to the model table (transitively equal).
- `planSceneLights(lights, level, decision)` — §41.1.2 rules 1/2/4: ambient
  → `(color, intensity)` with no position dependence; directional →
  `(color, intensity)` + derived position/target with `castShadow` exactly
  the decided state; at most one directional + one ambient node per realized
  scene.

**`src/adapter.ts`** (`createSceneAdapter`, the accepted options surface):

- v3 detection: `scene.schemaVersion === 3` + the `game.level` input.
- v3 lights: the authored `light` components are realized as
  `THREE.AmbientLight(color, intensity)` / `THREE.DirectionalLight(color,
  intensity)` with the derived position (`target − n·20`) and target (the
  shadow centre) — always, shadow state or not. The M1 hardcoded pair is
  emitted only for v1/v2 (unchanged).
- `surface` boxes: one `THREE.MeshStandardMaterial` per entity placement with
  the component values taken literally (no preset lookup) — owned per
  placement (value-level independence, §41.2.3); boxes without `surface`
  keep the M1 Lambert material (unchanged).
- WebGL-2 gate (hard, §41.1.4): a WebGL-1 context for a v3 scene is
  `render_unsupported` (the M3 target is WebGL 2, baseline.md §1); the
  accepted M1/M2 webgl1 fallback is unchanged.
- First-render shadow probe (§41.1.4, once per realized scene):
  `maxTextureSize ≥ 512` + a probe render with `shadowMap.enabled` +
  `THREE.PCFShadowMap` + the 512²/derived-camera parameters; a failure
  degrades soft (shadows off, key light only) and flips the diagnostic to
  `off`/`shadow_unsupported`. Scenes with no shadow-casting light never
  enable `shadowMap` (no map allocated, rule 5).
- Diagnostics gain the two §41.1.4 read-only fields: `shadows: 'on' |
  'off'` + `shadowReason?: 'cast_shadow_false' | 'shadow_bounds_exceeded'
  | 'shadow_unsupported'` (present iff off; recorded once per realized
  scene, never per frame; no path/token/device string). Construction state:
  v1/v2 and no-shadow-casting-light scenes ⇒ `off`/`cast_shadow_false`;
  bounds-exceeded ⇒ `off`/`shadow_bounds_exceeded`; else planned `on` (the
  real probe may flip it).

## Limitations

- Realized THREE light nodes, the WebGL-2 gate, the first-render probe and
  all pixels are browser-side; in-container evidence is the pure math +
  the construction-time decision/diagnostics (Node, stub canvas).
- `SHADOW_FAR_MAX = 200` is a safety bound that cannot bind with the frozen
  constants (with `halfExtent ≤ 64` the raw far is ≤ 86) — the `min` is
  implemented and the formula is asserted at the 64 boundary.
- The adapter's surface-material rule applies to `box` entities (this
  adapter's only primitive-mesh path); GLB model `surface` realization
  rides the GLB realization path (the per-entity instance rule is the
  same; wired into the full v3 preview in 59).
