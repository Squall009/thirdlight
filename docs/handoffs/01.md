## Outcome

M1 project data contract defined and fixture-pinned. One normative contract
document plus a machine-readable fixture index:

- **Documents/layout:** one project manifest (`project.json`) + one active
  scene (`scenes/main.json`); strict JSON, UTF-8, no BOM. File names are
  normative for schemaVersion 1; M1 is exactly one scene per project.
- **Version taxonomy (§6):** `schemaVersion` (M1: known `[1]`),
  `engineVersion` (semver, informational, never blocks validation),
  authoring `revision` (project-level, carried in the scene in M1; starts 0),
  runtime snapshot ID (derived, deterministic: `<projectId>@r<revision>`).
- **Coordinates (§2):** Y-up, right-handed, meters; local
  position/rotation-quaternion (`[x,y,z,w]`, three.js order)/scale; 2.5D
  movement plane XY with depth along Z; default camera orientation is
  identity rotation (looks down −Z, +Y up) at `[0, 0.5, 4]`.
- **Components (§10):** registry is exactly `{ transform, box, camera }`
  with exact fields, defaults, ranges, and validation; `transform` required
  on every entity; `box`/`camera` mutually exclusive; exactly one camera per
  scene; M1 limits (1024 entities, depth 32).
- **Hierarchy (§11):** forest; parent-before-child array order (display and
  paint order); missing-reference and O(n) functional-graph cycle rejection;
  M1 deletion = whole subtree; the camera cannot be deleted.
- **Validation/normalization (§12):** pure entry points
  (`validateManifest/Scene/Project`, `normalize*`, `migrate*`), 26 stable
  error codes with JSON-Pointer paths, collect-all-errors, strict unknown
  fields; unknown `schemaVersion` → exactly one actionable
  `schema_version_unsupported` error, document retained untouched; M1
  migrations = identity only (`no_migration_path` otherwise) — entry points
  described, no hypothetical migrations implemented. Canonical serialization
  is byte-stable (fixed key order, defaults filled, quaternions
  renormalized, idempotent).
- **Fixtures:** 3 valid (full demo project, minimal scene == §15 default
  scene, all-defaults-omitted) and 11 invalid (duplicate IDs, cycle, missing
  reference, invalid numbers/rotations, unknown component, two cameras,
  missing transform, unsupported future version, unsupported past version,
  intentionally non-strict JSON with `NaN`/`Infinity`, manifest/scene
  mismatch), plus the separately specified runtime NaN/±Infinity cases
  (R1–R6) since JSON cannot encode them.

No implementation was started: no code packages, no installs, no services.
