## Limitations / interpretations (no contract edits made)

1. **Released-project queries (§9.1 vs §9.3):** queries on a released
   project fail `workspace_closed` and never re-open; the next **command**
   re-opens, re-validates the (possibly edited) disk, and re-claims the
   released record at epoch+1 (record keeps original `openedAt`; release
   itself does not advance the epoch). §9.3's later, more specific
   statement was taken as governing. → *clarification request.*
2. **Own-record re-open is a byte-identical no-op** (no epoch advance, no
   rewrite): a backend re-opening its own live claim leaves the record
   unchanged — required by scenario 08's pinned "ownership record
   unchanged"; safe because `backendId` (128 random bits) + pid identify
   the owner. → *documented interpretation.*
3. **Second external change while pending:** paused mutations fail against
   the current pending (detection is at the next envelope write, §7.1);
   the re-fire (new snapshot, new hash) happens at the resolution write's
   pre-check. → *documented interpretation.*
4. **Top-level `project_unavailable.reason` for a JSON-garbage envelope is
   `json_parse_error`** (a permitted reason per the workspace.md error
   catalog), with `envelope_invalid` reserved for structure/`type`
   failures.
5. **Liveness start time** is computed from `btime` in `<procRoot>/stat`
   plus the per-process jiffies `starttime` — on this host `/proc/uptime`
   (and `os.uptime()`) is container-masked and inconsistent with the
   jiffies clock; `btime` shares the kernel clock with `starttime`.
6. **Config test seams** (`procRoot`, `stamp`, `pid`, `utcNow`, `ops`
   + `defaultWriteOps` export) are legitimate configuration (deterministic
   fixture-pinned tests); production defaults use the real
   `/proc`, wall clock, real pid, and real fs ops.
7. **Stale fixture divergence (not modified, both accepted):** the
   scenario-04 fixture generator hardcodes the quaternion error hint
   `"identity rotation is [0, 0, 0, 1]"`, while the accepted
   project-model emits a different hint (`normalize to unit length;
   e.g. 45-degree yaw…`, pinned by the model's own tests). Neither
   accepted artifact was changed; the workspace test blurs model-layer
   `hint`/`message` text inside `details` arrays and pins everything else.
   → *contract-change request: regenerate the fixture hint from the model.*
8. A manifest that is unloadable makes the directory `project_not_found`
   for commands/queries (commands.md §5.4), but `project_exists_invalid`
   (carrying the actual manifest load errors) for `createProject` onto
   that directory (workspace.md §8.1).
