## Review correction (2026-09-17, pre-commit)

A pre-commit review found one normative bug in the delivered contract text
and the same bug in the fixture tool, both in the `restoreSubtree` inverse
(commands.md §9.1): it specified insertion at position `index − k` (k = the
entry's position in the ascending-index list), which corrupts multi-entity
subtree restores (counterexample: pre-deletion `[A, B, C, D]` with `C` a
child of `B` restored to `[A, C, B, D]` — child before parent). The formula
now reads: insert in ascending `index` order, each at position `index`
(its pre-deletion array index), which exactly reconstructs the pre-deletion
array. `restoredParentId` is restated as the root's parent (always a
survivor of a subtree deletion). No committed fixture is affected — every
fixture restore is a single-entity subtree — so all 71 generated files are
byte-unchanged. The tool's `applyRestore` was corrected to match, and a new
multi-entity restore round-trip self-check (A,B,C,D,E counterexample) now
runs on every `--check`; it fails under the old formula.
