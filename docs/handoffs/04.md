## Limitations

- Check 1 is a static pattern scan of the three normative specifier forms;
  `require()` / `import =` are outside the contract's scan spec;
  import-like text in comments/strings can produce false positives (no
  false negatives for the normative forms); `exports` subpath patterns
  (`./x/*`) are not matched (M1 maps are flat tables — §3).
- check-deps compares `npm ls --depth=0` (direct deps) plus declared
  package.json specs; a pin absent from the lockfile is *pending*
  (consumer unit unimplemented — §2), not a failure.
- Workspace-internal declared deps must be exact and equal the target's
  current version — a documented reading of §5.6's "exact pinned versions
  (no ranges)".
- `npm test` currently runs the check-tool suite only (35 tests); product
  tests begin with packet 05.
- `dist/editor/main.js` / `dist/preview/preview.js` output file names are
  the packet 04 build choice (the contract pins the directories,
  sessions.md §13.7).
