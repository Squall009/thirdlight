# Packet 10 — Minimal visual editor + isolated play

## Outcome

**Packet 10 implemented.** A new `@thirdlight/editor` package provides the
minimal visual editor and the isolated, separate-origin play preview, on top
of the packet 08 runtime/adapter and the packet 09 backend transport.

- **React + `@types/react` + `@types/react-dom` installed** at the §7 pins
  (`react@19.3.0`, `react-dom@19.3.0`, `@types/react@19.3.0`,
  `@types/react-dom@19.3.0`), **exact, editor-scoped only** (decision 0001 §10).
  The viewport, gizmo, and picking stay imperative and React-free.
- **Editor package** with two layers:
  - **Pure, Node-testable logic** (no DOM): `session/projection` (projected
    browser state — hydration from full state, `mutation.applied` application
    with requestId dedup + a stale-resync gap rule, document order,
    `ChangeData` create/setTransform/delete/restore), `session/gesture`
    (local no-traffic preview, exactly one undoable commit, ≤1 auto-rebase on
    `revision_conflict`), `session/envelope` (request envelopes, `requestId`
    idempotency, duplicate-response detection, lost-ack retry decision),
    `preview/bridge` (the `postMessage` bridge — exact `event.origin` +
    trusted-source checks, nonce handshake, allowlisted message validation,
    bounded drop counters, never `targetOrigin:"*"`).
  - **Browser layer**: `session/client` (the WS authoring transport —
    establish, upgrade, full-resync, `mutation.applied`, play, command with
    lost-ack retry + conflict), `viewport/viewport` (imperative three.js
    scene/camera/renderer + orbit + picking + projection sync),
    `viewport/gizmo` (translate/rotate/scale local preview, one commit),
    `ui/App` + `Hierarchy`/`Inspector`/`Toolbar`/`StatusBar` (React panels),
    `preview/preview-bootstrap` (the separate-origin preview: runtime +
    adapter, demo, bridge relays, no credentials), `index.tsx` (entry).
- **esbuild TSX loader build** (decision 0001 §10): the editor build now
  emits `dist/editor/main.js` + `dist/editor/index.html` (with a
  build-injected `window.__thirdlightEditor = { v, projectId,
  previewOrigin, authoringToken }`) and `dist/preview/preview.js`. The
  preview page (served by the backend) carries only `{ v, authoringOrigin }`
  — **no credentials**.

## Acceptance criteria (m1-acceptance §2.2 packet-10 rows)

- **PASS — editor gesture has no per-frame traffic + exactly one commit +
  conflict recovery** (`gesture.test`): the gesture emits zero commands while
  previewing; on end it commits exactly one `setTransform` with the base
  `expectedRevision`; on `revision_conflict` it rebases once from
  `currentRevision` and retries; a second conflict is surfaced (not lost).
- **PASS — preview receives no credentials** (`bridge.test` + bundle scan):
  no preview message/constructor accepts a token; the preview bundle has no
  authoring token/API URL; the preview template carries only `{v,
  authoringOrigin}`.
- **PASS — bridge exact origin/source/nonce** (`bridge.test`): messages from a
  mismatched `event.origin` or untrusted source are dropped (counted); the
  nonce handshake is required; wildcard `*` is never used; all messages
  validate against the protocol allowlist.
- **PASS — browser state is a backend projection** (`projection.test`):
  `mutation.applied` advances the projection; unknown/stale `requestId`s do
  not create phantom state; a revision gap triggers a resync signal (the
  editor re-fetches full state) rather than trusting the browser as source.
- **PASS — esbuild TSX loader** (build + typecheck): the editor build
  succeeds with the TSX loader under tsc 5.9.3 strict.
- **PASS — preview/bridge isolation + relay** (unit + backend integration):
  the preview is separate-origin and backend-free; the editor relays
  `tl.snapshot`/`tl.play.*` through the WS owner (packet 09) and forwards to
  the preview via the validated bridge.
- **UNVERIFIED — in-browser visual behavior** (see Limitations): editor
  render/selection/gizmo drag, preview WebGL oscillation + snapshot revision
  HUD, play/stop round-trip in a real browser, screenshots, and the
  reload/orphaned-preview re-handshake flows could **not** be exercised here.

## Limitations

- **Visual / WebGL verification is UNVERIFIED** (no browser or `libnss3` in
  this container — same constraint as packet 08). The imperative viewport,
  gizmo, React panels, and preview render path are type-checked and their pure
  logic is unit-tested, but they have **not** been run in a browser.
  **Manual steps to verify** (needs a host with a browser):
  1. `npm run build`, then `THIRDLIGHT_PROJECT_ID=demo-0001 THIRDLIGHT_PREVIEW_ORIGIN=http://127.0.0.1:8502 THIRDLIGHT_EDITOR_TOKEN=<authoring-token> npm run build` (regenerate the editor page with a real token), then start the backend with `editorStaticDir=dist/editor`, `previewStaticDir=dist/preview`, `authoringOrigin=http://127.0.0.1:8501`, `previewOrigin=http://127.0.0.1:8502`, and an authoring token.
  2. Open the authoring origin: the Hierarchy shows `Root > Demo Box`; select the box and confirm the Inspector shows its transform; drag the gizmo — the box previews locally with **no** per-frame network traffic, and on release exactly one `setTransform` is sent (check the WS log / `queryProject` revision +1).
  3. Press Play: a preview tab opens on the preview origin; confirm the demo box oscillates ±0.5 m, the play panel **and** preview HUD show the snapshot revision (e.g. `demo-m1@r4`), and `play.started`/`play.preview.ready` are emitted. Screenshot at t≈0 and t≈2 s.
  4. Confirm the preview page (DevTools) has **no** credentials and never calls the backend (Network tab: no `/api/v1/`).
  5. Stop play; the preview tears down (no WebGL context leak on repeated start/stop); the authoring scene is unchanged by play.
  6. Reload the preview during play → it re-handshakes and resumes (owner connected); reload the **editor** during play → `session_lost`, and the orphaned preview is terminated within ~30 s.
- **No assets, input, or physics** in the preview (M1 scope, §7.3/§10): only
  the built-in demo module runs.
