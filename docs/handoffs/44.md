## Contract-change requests

1. **CC-44-1 — the model-owned v3 envelope entry point is uncontracted.** §16.9
   lists no envelope entry point, yet 44 must run the envelope fixtures and 46
   must share one implementation. Proposed §16.9/§3 diff: add
   `validateEnvelopeV3`/`normalizeEnvelopeV3`/`parseEnvelopeV3`/`parseSceneV3`,
   `EnvelopeV3Load`/`EnvelopeV3Error`/`EnvelopeV3ErrorCode`,
   `canonicalContentV3`, `validateGameConfig`, the six component validators, and
   the v3 envelope branch's two envelope-level reasons.
2. **CC-44-2 — promoted §18.5/§18.6 conflict with the committed audio
   fixtures**, which are marked packet-41 placeholders (`recipeVersion: 0`,
   `toolchain: {}`, `extensions: []`, all-zero legacy `AssetMetrics`) the
   promoted `pcm-wav`/`PcmWavMetrics` rules reject. 44 validates the audio
   container structurally only. Proposed: regenerate
   `catalog/audio-asset-record-v3.json` and
   `envelope/valid/demo-0003-media-v3.json` to §18.5/§18.6 in a bounded fixture
   repair, then enforce those rules.
3. **CC-44-3 — `migration/v2-source/envelope.json` is not a loadable v2 scene**
   (declares `schemaVersion: 2`, carries the v3-only `cameraFollow`), against
   §16.5.1. 44 validates the v3 *result* (superset registry). Proposed: correct
   the fixture, or add to §23.11/§16.5.1 "a `schemaVersion` 2 source whose
   values are valid in v3 is accepted".
4. **CC-44-4 — the contracted migration destination is not loadable.** §16.5.2
   copies content verbatim and resets `revision` to 0, while §18.9.2 rule 4
   requires `publishedRevision ≤ scene.revision`; the destination fixture
   (asset `publishedRevision: 2`, revision 0) fails the §13.2 cross-block check
   (pinned by a test). Proposed: reset derived revision metadata
   (`publishedRevision`, `source.publishedRevision`,
   `behaviorTrust[].acknowledgedRevision`) to 0 on copy in §16.5.2.
5. **CC-44-5 — the promoted §18.9.3 code/limit set cannot be completed by its
   owner.** `animation_role_*`, `animation_skin_unsupported`,
   `animation_root_motion`, `asset_empty_model`, `asset_extension_unsupported`
   and the media limit names are not added to `ERROR_CODES`/`LimitName` (their
   validation is 41/47's; 47 may not edit `project-model`). Proposed: grant 47
   a bounded re-open of `errors.ts`.
6. **CC-44-6 — capture precedence is unstated.** §19.2/§16.6 item 4 hold "one
   entry per reachable asset" while a `modelAnimation` binding "pins its
   recorded version explicitly in addition to the asset's `currentVersion`".
   44 resolves deterministically (explicit version wins; first binding wins if
   two differ). Proposed: state the precedence in §19.1/§16.6 item 4.
