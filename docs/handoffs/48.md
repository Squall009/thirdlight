strict inbound validation. `errors.ts` gains the §20 closed code set +

kind/role-aware injection: `{kind:"audio"}` → `inspectAudio` with

upload→inspect→`publishAsset`.

**Migration route.** `POST /api/v1/admin/projects/:projectId/migrate-copy-v3`
(admin scope, C35-4-style additive operator route) delegates to
`service.migrateProjectCopyV3`, returns the §16.5.2 object verbatim and the
§16.8 codes; refusals write nothing. **Game relay.** `PlayManager` gains the
bounded §20 control/observe relay (one pending relay per play, request-driven
timeout, last-known run identity advanced only forward, `finishStop`/`dispose`
teardown) with the two new routes, the two WS acks routed to the relay map, and
the closed failure mapping. No simulation, no credential/capability/binary
crossing. **MCP.** Real `tl_game_control`/`tl_game_observe` tools +
`BackendClient.gameControl/gameObserve`; `tl_command` advertises the v3 ops;
`tl_content_upload` gains `kind`/`animation`.

**CC-47-5 — independent read (confirmed).** §41.4.5's
`AUDIO_MAX_REFERENCED_CUES = 6` is **structurally unreachable**, not merely
unenforced. The reference sites are (a) `content.game.cues`, exactly five fixed

tautology, not a limit. Proposed: mark it "maximum, not a rejection bound" (or
drop the code) in §41.4.5/§41.7.1.
