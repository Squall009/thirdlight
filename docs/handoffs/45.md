# Packet 45 — Pure game and presentation commands

**Executed 2026-09-19. `@thirdlight/commands` implements the promoted v3
game/presentation command surface on the existing history engine; the committed
packet-39 command fixtures replay through the real `applyMutation`. No

under `packages/commands/src/`.**

## Outcome

The v3 surface (commands.md §§2/3.1/5.3/5.4/8.5.1/8.10/8.13–8.14; authoring
§§A3–A8; project-model §23) uses one mutation path: `createEntity` add-capable
`components` + `surfacePreset` with the derived-ID prefix rule
(`model`→`box`→`zone`→`spawn`→`light`→`group`); `setComponent` add/edit/remove
for the six v3 components (plus the M2 kinds) with the §41.3.2 role stages 2–4;
`applySurfacePreset`; `setGameConfig` create/partial-edit/remove plus
`queryGameConfig`; the `queryEntities` component filter and v3 content counts;
`publishAsset` `kind` (`model`/`audio`) and the atomic §8.5.1 `animation`
reimport. Reference safety is rejection-first (project-model §23.6): a
deletion/removal that would dangle a game/checkpoint reference fails with
`game_reference_in_use`; nothing is cleared. Validation order, one revision +
one history entry per success, redo invalidation, exact-ID redo/retry and the
no-change check are unchanged from M1/M2.

The v3 result gate re-validates scene+content together via `validateEnvelopeV3`
(or `validateProjectV3` with a manifest) and maps envelope-relative paths back
to document-relative `details`; the M1/M2 gates are byte-identical.

**Mutation ops:** `createEntity` (extended), `setTransform`, `deleteEntity` (v3
reference check), `undo`, `redo`, `publishAsset` (kind + animation),
`publishBehavior`, `setBehaviorProperties`, `setComponent` (extended union),
`setSettings`, `acknowledgeBehaviorTrust`, `createPrefab`,
`instantiatePrefab`, `applySurfacePreset`, `setGameConfig`. New queries:
`queryGameConfig`, `filterEntitiesByComponent`, v3 `contentCounts` keys.
