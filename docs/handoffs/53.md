## What was implemented

**`packages/three-adapter/src/animation.ts` (new)** — the approved role
selector and bounded crossfade (presentation.md §41.3.6/§41.3.7/§41.9, root
subpath, no new subpath):

- `createAnimationRoleController(instance, view)` → `AnimationRoleController`
  (`setRoles(roles, version)` / `update(deltaSeconds)` / `state()` /
  `dispose()`). One `THREE.AnimationMixer` per instance rooted at the
  instance holder (rule 5: independent pose/mixer per copy — no global
  mixer, no shared action, no shared clock); one `AnimationAction` per role
  (≤ 3 actions). The controller installs **no** rAF/timer/mixer listener and
  reads **no** clock (rule 2): `update(deltaSeconds)` is the host's one
  frame advance, bounded to `0 ≤ delta ≤ 0.25` (`preview_invalid` otherwise).
- Rule 3 selection is the pure `selectAnimationRole(motion)` (airborne iff
  `!grounded`; run iff `speed > RUN_SPEED_EPS = 0.05`; else idle) — a pure
  function of the committed view the host passes in (§41.3.7 slice:
  `stepIndex` + `playerMotion`; the controller never references the runtime,
  never samples input, never writes any transform — rules 1/6).
- Rule 4 crossfade: exactly `ANIMATION_CROSSFADE_SECONDS = 0.2` via
  `crossFadeTo(fadeIn, 0.2, false)`; the first advance activates the selected
  role at full weight (no fade); a change while blending retargets the fade
  (the previous incoming becomes the outgoing). `blending` is true while the
  0.2 s fade runs.
- Rule 7: `setRoles` re-checks the committed mapping against the **loaded**
  clips — stale version (stale-load guard, §41.3.4 rule 6 / "authored bytes
  stay pinned during active play"), stage 3 range, stage 5 name equality,
  stage 6 ambiguity — and returns the hard `animation_role_unresolved`
  (registered in `ERROR_CODES` at 52) with a bounded message. A rejected
  mapping installs nothing: `update` succeeds with no mixer activity (the
  host renders statically). Stage 4 (role duplicate) stays at publication —
  it is version-independent.
- Rule 8: `dispose()` is safe mid-blend and idempotent (`alreadyDisposed`);
  it stops/uncaches the actions and releases the mixer exactly once. The
  controller is tracked by its instance: `ModelInstance.dispose()` releases
  each tracked controller exactly once (§41.6 mixer row), and creating one
  for a disposed instance is `asset_disposed`.
- `state()` reports `{ role, weights: {idle,run,airborne}, blending,
  stepIndex }` — the last committed step the selector consumed.
- Constants exported: `RUN_SPEED_EPS`, `ANIMATION_CROSSFADE_SECONDS`,
  `ANIMATION_MAX_DELTA_SECONDS`, `ANIMATION_ROLES` + the pure
  `crossfadeIncomingWeight(t)` / `validateAnimationRoles(…)` helpers (the B14
  checklist and tests compare realized values against these).
