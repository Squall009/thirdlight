## Limitations / interpretations

- **Jump cue derivation**: the closed `GameEventKind` has no jump event;
  the host derives the jump cue from the committed `playerMotion`
  grounded→airborne transition (a walk-off cliff also fires it — a
  documented limitation of the committed-view vocabulary).
- **Consumption only on menu action**: the host marks the confirm
  consumed when it DROVE start/replay; a confirm sampled in play is a
  no-op and keeps its jump (B15 feel; §4.2 targets consumed menu presses).
- **BUILTIN_MODULES**: registered per §3.2 ("runtime built-ins"), not
  selected; the §4.1 row names three runtime values — a 4th (minor, the
  package edge is unchanged).
- `readArtifact` returns `Promise<ArrayBuffer>` (contract shape); the host
  wraps for the owner's `Uint8Array`. `settings` typed `GameplaySettings`
  (= the contract's six numeric keys). The host never disposes the
  injected input/audio owners (the §3.1 reuse clause).
- The host's own visibility→audio-hidden listener is NOT wired (the input
  owner's visibility handling + the owner-level `setHidden` are the
  verified halves; the page wiring lands with the 59 preview wrapper).

## Contract-change requests

- **CC-55-1 (additive)**: `GameHostConfig.buildId: string` +
  `assetPaths?: Record<string, string>` — `GameHostObservation.buildId` is
  unsatisfiable from the binding config (no build identity) and the host
  cannot resolve cue bytes (the manifest is wrapper-owned; the host is
  fetch-free). The wrapper passes the verified manifest buildId + the
  manifest asset paths.
- **CC-55-1b (additive)**: `GameHost.runtime` — the read-only runtime seam
  (the binding surface exposes no frame-advance handle; manual-driver /
  Node compositions and the 59 bridge need one).
- **CC-55-2 (additive, deviation)**: `GameHostConfig.adapter` is the
  FACTORY `(runtime) => adapter | null` — the three-adapter instance
  requires the runtime it renders, which the host creates inside `mount()`;
  a pre-made instance cannot be injected.
- **CC-55-3 (open)**: the §3.1 config has no behavior-linking channel; the
  55 composition rejects behavior-carrying scenes fail-closed. Required by
  56/59 if a delivered game carries behavior records.
