## Contract of record (`planning/m4-contracts/templates.md`)

- **One versioned built-in template** (`platformer-starter` v1), directory
  form: `descriptor.json` + `base/scene.json` + `recipe/commands.json` +
  `sources/**` + `NOTICE`. Three independent digest checks (descriptor /
  recipe / each blob); no archives, no symlinks, no scripts, no URL fetch —
  the only interpreter is the accepted command engine applying JSON
  commands. Engine-version rule: exact match (CCR-65-2, proposed; inert at
  the `0.1.0` baseline).
- **`createProjectFromTemplate`** (new workspace operator): five phases —
  `reserved` (atomic-mkdir claim + reservation marker) → `blobs` (digest-
  verified copies into the accepted content store) → `envelope` (manifest
  **v2** + base scene at revision 0) → `replayed` (the 30-command recipe
  through the accepted command pipeline) → `published` (ownership claim,
  marker removed). Full crash-completion table per phase boundary; a
  partial destination is **not a project** (refused
  `template_initialization_incomplete` — C09's no-ready-partial invariant).
  Idempotency: an identity-matching retry is a no-op; anything else is
  `template_destination_exists` (never overwritten). Concurrent claims
  converge or conflict (marker-carried identity). Installed-template
  removal/replacement: created projects unaffected (no live reference);
  new creations record the replacement's identity; an in-flight creation
  whose template vanished ⇒ `template_source_unavailable` (never
  re-pointed).
- **Schema bump (named):** manifest `schemaVersion 2` + required
  `template` block (`templateId`, `version`, `contentDigest`,
  `engineVersion`). Only `(manifest 2, storage 3, scene 3)` is the new
  valid combination; migration never re-versions (the accepted rule,
  unchanged); plain `createProject` still writes v1. No migration needed.
  `queryProject` carries the v2 manifest with **no query-shape change**.
- **Revision/retry/history (frozen):** recipe requestIds are
  `req-` + first 32 hex of `sha256("<templateId>@<version>#<i>")` (the
  accepted `^req-[0-9a-f]{32}$` shape); N ≤ 128 = the retry retention, so
  the whole starter is dedup-safe across crash re-execution. The starter
  is N ordinary undoable history entries — no composite undo, no magic
  entry.
- **Modules (finite registry, C06):** the M4 approved set is the three
  platformer core modules + the M1 demo (optional) + the
  `thirdlight.behavior:<id>` reference pattern (not linkable under the
  built-in-only profile ⇒ `module_unresolved`, the C14 explicit refusal —
  never a silent omission). Resolution runs at creation, every capture
  (Play/export snapshot build) and after edits; the panel/layout state is
  **never** an input.
- **Panel visibility (C06):** a frozen 7-panel registry (hierarchy,
  inspector, assets, media, prefabs, behaviors, gameplay); preferences are
  browser-local per-project `localStorage` (disposable), seeded from the
  template layout for new projects; corruption resets safely; hiding a
  panel never touches the envelope, revision, module closure, assets,
  runtime closure, export or the backup (byte-absence invariant).
- **Authorization:** creation is admin-scoped (new route
  `POST /api/v1/admin/templates/projects`); a project-scoped MCP token
  cannot create projects (new admin-only tool `tl_project_create` +
  read-only `tl_templates_list`). Origin kind `template` is PROPOSED
  (C65-7) — pre-promotion the accepted engine's origin validation
  (browser|mcp|admin) rejects it (verified live this packet), so the
  fixture replay uses the documented `admin` substitution (an audit tag —
  no semantic effect).
- **No new package/dependency/bundle** (dependencies.md no-change
  adjudication): `templates/` is engine data.
