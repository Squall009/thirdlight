## Outcome

**Implemented and complete, awaiting review.** The
`@thirdlight/project-model` package (zero-dependency leaf of the node-side
graph, dependencies.md §4.1) now provides the project data contract
(project-model.md) as a working module:

- **Public API** (index.ts, per dependencies.md §3): `parseManifest`,
  `parseScene`, `validateManifest`, `validateScene`, `validateProject`,
  `normalizeManifest`, `normalizeScene`, `serializeCanonical`, `migrate`,
  plus the public types (`Manifest`, `Scene`, `Entity`, `ComponentMap`,
  `TransformComponent`, `BoxComponent`, `MaterialComponent`,
  `CameraComponent`, `SceneSummary`), `ModelError`/`ERROR_CODES` (24 codes)
  and the `ModelResult`/`SerializeResult` shapes. In M1
  `normalize*` ≡ `validate*` (both return the canonical document; the
  split stays for later packets).
- **Strict byte parser** (parse-bytes.ts): UTF-8 validation (fatal), BOM
  rejection, a two-pass strict JSON parser (syntax pass, then
  duplicate-key tracking) with exact byte-offset → JSON-Pointer
  error mapping, decoded duplicate-key names, JS number semantics for
  exponent overflow (`1e400` ⇒ non-finite, valid syntax), and trailing
  garbage rejection.
- **Boundary validation** (validate.ts): schemaVersion gate (pass 3 —
  exactly one `schema_version_unsupported` with `found`,
  `knownVersions: [1]`, and a direction hint; no deeper checks, no
  destructive rewrite); hierarchy/reference rules (unique IDs,
  `parent_id` existence + type, no cycles, parent-before-child order,
  depth ≤ 32 with a 32-ok/33-fail boundary); strict field sets at every
  level (unknown ⇒ `field_unexpected`, nothing stripped); transform /
  box / material / camera field rules with §10 ranges; finiteness before
  range checks; M1 limits (≤ 1024 entities). Errors carry bounded,
  JSON-safe `found` values (never raw NaN/Infinity).
- **Canonical serialization** (normalize.ts): stable field order per
  §12.2 (schemaVersion, sceneId, revision, entities → id, name,
  parentId, components → transform → position, rotation, scale;
  box → size, material; camera → type, fovY, near, far), defaults
  filled, `-0` normalized to `0`, quaternions never renormalized (q and
  −q both accepted). Byte-stable: idempotent and byte-identical to the
  golden `expectedNormalized` fixture files.
- **Migration entry point** (migrate.ts): identity for 1 → 1;
  `no_migration_path` for any other version (no M1 migration paths
  exist yet).

No renderer, UI, server, or command code was added. Only the package,
its tests, and the workspace lockfile registration changed.

## Acceptance criteria

**Passed**

- Public types, runtime validation, serializer/parser, minimal component
  definitions — implemented; TS types alone are never trusted, all
  parsed values are re-validated at the boundary.
- Valid roundtrip — every `valid/` fixture parses and validates;
  canonical output is byte-identical to the golden files; reparse of
  serialized bytes is byte-idempotent.
- Each agreed invalid fixture — all `invalid/` fixtures (and the
  `mixed-schema-versions`, `manifest-scene-mismatch` projects) are
  rejected with the **exact** expected code sets per
  `expected.json` (indexVersion 2), including error counts;
  byte-input cases B1–B11 (`byte-input-cases.md`) and runtime cases
  R1–R6 (`non-finite-cases.md`) all pass.
- Hierarchy/reference rules — duplicate IDs, missing/invalid
  `parent_id`, cycles, child-before-parent, depth 33 rejection,
  1025-entity rejection, all verified with exact codes and paths.
- Unsupported version without destructive rewrite — v0/v2 scenes and
  projects yield exactly one `schema_version_unsupported` (with
  `found`/`knownVersions`/hint) and the input bytes are verified
  untouched after the call.

**Failed:** none. **Unverified:** none required — this packet has no
visual behavior to verify in a browser (pure model layer).

## Limitations / honest notes

- **Fixture reading in tests:** project-model's boundary rules forbid
  Node builtin imports in *all* package sources — the check
  (dependencies.md §5 check 1) scans test files too and its only test
  exemption is the approved runner (vitest). The workspace also has no
  `@types/node`/Vite client types (no new dependency per §7). The tests
  therefore read fixtures through the Vite `import.meta.glob(...,
  { query: '?raw' })` transform (verified working on the pinned
  vitest 5.0.1, including upward relative patterns) and type it via a
  narrow ambient `ImportMeta.glob` declaration (`vite-glob.d.ts`).
  Fixture files are valid UTF-8 (packet 01 verification), so the raw
  text round-trips to exact bytes via `TextEncoder`.
- **Debugging record:** verification surfaced three real bugs that were
  fixed and are now pinned by tests: an inverted trailing-garbage check
  in the strict parser, a depth-walk that failed to resolve chains
  ending at a root, and camera fields being required instead of
  optional-with-defaults.
- `migrate` is identity-only for v1; a real migration table arrives
  with a schema v2 (out of M1 scope).
