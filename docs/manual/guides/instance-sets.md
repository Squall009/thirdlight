# Dress a scene with instance sets

**Goal:** many copies of one model — rocks, grass, crates, posts — drawn
cheaply, placed by hand with a brush or from a list. Every setting is in
[Instance sets](../features/instance-sets.md).

An instance set is one object that draws up to 65,536 copies of one model.
Copies have no ids, colliders or scripts. For copies a player interacts
with, use objects or prefabs; for copies laid by rules over terrain or
blocks, use [rule scatter](terrain.md#rule-scatter-and-ground-cover) (see
[which tool](which-tool.md)).

## In the editor

1. **GameObject → Instance set…**: pick the model, the count, the width
   and depth of the area, the scale range and the random turn. The set is
   scattered round the point the camera looks at; the same seed gives the
   same layout.
2. With the set selected, its Inspector shows **Paint** and **Erase** and the
   brush: **Radius**, **Density** (copies per m²), **Spacing**, **Scale
   min/max**, **Rotation** and **Align** (0 upright, 1 along the surface).
   Drag in the Scene view: copies land on anything that collides — block
   layers and objects with a collider. One stroke is one undo step.
3. Click one copy in the Scene view to move, turn or scale just that copy
   (W/E/R), or **Del** to remove it; **Whole set** goes back to the set.

## Through the API

1. Publish the copies' placements as a buffer: 10 numbers per copy
   (position xyz, rotation quaternion xyzw, scale xyz), local to the object.
   `POST /api/v1/projects/<id>/content/buffers` with
   `{"transforms": [x, y, z, qx, qy, qz, qw, sx, sy, sz, …]}` (up to 4,096
   copies inline) answers `{"ok": true, "digest": "…", "count": 50}`. MCP:
   `tl_instance_buffer {transforms}`.
2. Make the set: [`createEntity`](../reference/ops-detail.md#op-createEntity)
   `{"sceneId": "scene-main", "kind": "group", "name": "Rocks", "components": {"instances": {"asset": {"assetId": "<model>"}, "buffer": "<digest>", "count": 50}}}`
   ([`instances`](../reference/components-rendering.md#component-instances)).
3. Brush strokes: [`paintInstances`](../reference/ops-detail.md#op-paintInstances)
   `{"entityId": "<set>", "mode": "paint", "dabs": [[12, 1, 12], [13, 1, 13]], "brush": {"radius": 3, "density": 0.5, "spacing": 1, "scale": [0.8, 1.2], "yaw": 360, "align": 0, "seed": 7}}`.
   The same stroke always gives the same copies; painting it again adds
   none.
4. Edit single copies: read the list (`tl_instance_buffer {digest}`, or
   `GET …/content/buffers/<digest>`: the raw float32 values), change it, publish it again and store
   it with [`setComponent`](../reference/ops-detail.md#op-setComponent)
   `instances {buffer, count}` — one undo step.

## Which to use

Paint in the editor where the look matters: you see where copies land. Use
the API for copies that come from data — a forest generated by your own
tool, posts every 2 m along a list of points — and keep that tool in your
repository so you can run it again.

## Pitfalls

- **An API brush stroke lands only on block layers.** The editor sends the
  surface it found under the pointer; a `paintInstances` without `surface`
  uses the scene's block layers, and a stroke over nothing is refused with
  `no_change`.
- **Instance sets cast no shadow unless they say so** (`castShadow: true`).
  Foliage rarely needs one; see the foliage policy in
  [Terrain](../features/terrain.md#foliage-best-practice-the-foliage-policy).
- **Thin far copies out.** Set **Thinnest density** (`densityMin`, 0.25 is a
  good start): sets made before thinning existed draw every copy.
- **A long drag is several strokes** (256 dabs and 1,536 places each), so it
  takes several undos to take back.
- **No colliders.** A copy the player must bump into needs to be an object
  with a collider, or a scatter rule with **Collides**.
