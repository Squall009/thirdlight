# three.js upgrade checklist

The engine pins three 0.187.0 (r187). A few renderer hooks reach into three's
private or undocumented members because r187 has no public way to do what
they do. Almost all are guarded by `typeof` checks: on a three whose
internals moved they install nothing and throw nothing, so a broken hook
shows up as a hitch, a leak or wrong shading, never as an error. Their unit
tests run against hand-written fakes of three's behaviour, so they keep
passing whatever three does. A newer three is first assessed against this
list (release notes read, impact on every row written into the phase plan);
it is taken only when the owner authorizes it, and then goes through this
list before it lands.

All paths are under `packages/three-adapter/src/` unless they say
otherwise. Most hooks are installed in `renderer-factory.ts`
(`registerLayeredLights`, `registerProbeLighting` round line 340; the
build hooks round line 520).

## 1. Read the release notes against these members

For each row, check the new three's source for the member, its signature
and the behaviour the hook relies on. A rename or a changed meaning is a
change to the hook (or its removal, if three now does the job itself).

`node tools/three-hooks.mjs` lists every hook site with its file:line and
the member it uses (prototype patches, replaced instance methods,
`_`-prefixed members, node builder members);
`tools/three-hooks.test.mjs` fails while a site's file and member are not
named together in one row below, so a new hook lands with its row.

## 5. Upgrade notes

### r186 → r187 (0.186.1 → 0.187.0)

Read against the r187 release notes, the migration guide and a diff of the
two packages' `src/` and `examples/jsm/`.

- **Removed, three does it now:** the lighting cube (`environment-cube.ts`:
  r187's PMREM is a cube render target with a mip chain per roughness, read
  with one lookup a term, which is what the cube copied it into); the WebGL 2
  vertex array sweep, program and shader deletion and texture-listener release
  (`dispose.ts`: r187 releases VAOs by reference count, deletes programs and
  shaders in `_releasePipeline` / `_releaseProgram`, and drops its texture
  listeners on dispose); the lose-context override (r187 keeps the context of a
  canvas it was given); the editor's OrbitControls key-listener release (r187
  adds and removes them on the canvas's own document).
- **Changed:** `library.addLight` → `Light.registerNode` (deprecated in r187,
  now one registration per light class); `_isPreCompiling` →
  `_precompilationState` (`shadow-casters.ts` `isPreCompiling`), without which
  shadow maps were drawn in every precompile; `disposeSharingGeometry` (three's
  geometry record is `get(geometry)`'s `onDispose` and a tracked weak
  reference; attributes are keyed by their GPU buffer, an interleaved
  attribute's `data`, also in `releaseNodeAttributes`); `instanceOrigin` marks
  its build `objectSpecific` (r187 shares `InstancedMesh` builds, which would
  have read another mesh's matrices); `ObjectTextureNode` no longer calls a
  `TextureNode.update` that is gone; the reflections pass and the motion node
  extend `Node` (`TempNode` is deprecated and warns per construction); the
  temporal upscale builds its inputs first and drops `_needsPostProcessingSync`;
