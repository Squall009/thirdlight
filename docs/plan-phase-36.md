# Phase 36 — The block editor, kits and the trim sheet spec

Goal: going from a kit to a built level feels like one workflow. A **kit**
is one project item holding:
- a trim sheet;
- the style presets that use it;
- block types;
- pieces for doors, windows and the like.

The engine ships a **Basic Kit**, so a new level never draws grey. The
**block editor** is a full-screen edit mode in phase 34's shell. Its palette
comes from the kit, every block-type setting is editable in the UI (models
included), and rooms and buildings are a clearly named mode. Trim sheets
follow a **written art spec**, shared with the Texture Designer, and trims
are drawn at their real height instead of being stretched.

Read `plan-phase-34.md` and `plan-phase-35.md` first. The engine never
reads the game repos; nothing here is fitted to one game.

**Release checks run when the phase starts (36.0).**

## 1. Owner decisions (2026-10-12)

- **Kits as one item: yes.**
- **The block-kit workflow must explain itself.** The owner's questions
  were: must I supply meshes, or does Thirdlight have a basic geometry kit
  (ground, walls, stairs, buildings, interiors) that custom models such as
  doors and windows supplement? And what spec must a trim sheet follow to
  work with every kit?
- **Block layers blend four materials** like terrain. Built in phase 35;
  the block editor's paint uses it here.
- *Proposed, default chosen, owner to confirm:*
  - **"Kit swap" is renamed "Themes"** in the UI and manual. The data key
    `kits` on block types and layers stays, so no format change.
  - **A Kit references its parts.** It doesn't copy them: block types,
    presets and the trim material stay ordinary items and can belong to
    several kits.
  - **The Basic Kit is engine content.** It is read-only; **Derive** makes
    an editable copy, as starter presets work today. Its prototype trim
    sheet and placeholder door/window are game-ready assets with their
    triangle counts, LODs, collision, texture sizes and file sizes recorded
    in §5.
  - **Trim sheet defaults move to the Texture Designer's:** 2048², 512 px/m.
    The art-factory side is proposed to the owner separately (that repo
    isn't edited from here).

## 2. Where things stand (recon 2026-10-12, at `47999af5`; re-read at `6f191f50` after phase 35)

- **"Kit" means four things today:**
  - block-type "kits", a remap only (`block-kit.ts`);
  - "kit models", GLBs of named pieces (`three-adapter/src/pieces.ts`);
  - the `kit` shader (shown as "Atlas surface" since phase 35, `MATERIAL_SHADER_LABELS`);
  - in the manual, loosely, generated architecture.
- **The real built-in geometry is generated architecture**
  (`arch-generate.ts`, `arch-sweep.ts`, `arch-fill.ts`, `arch-roof.ts`,
  `arch-rooms.ts`):
  - walls, floors, ceilings, vaults, roofs, stairs, openings, frames,
    mouldings, buildings and interiors;
  - starter styles and presets in `arch-style-starters.ts` (room, tall
    room, hall, rail, fence, pipe), with `sheet: ''`;
  - with no trim material it draws flat grey (`architecture-view.ts:1266`).
- **Block types draw as coloured stand-ins** of their collision shape
  (`block-mesh.ts`). Under a trim material (or a layered surface with a
  trim layer) block faces wear strip UVs since 35.9 (`three-adapter/src/block-cell-uv.ts`):
  first storey `lower_wall`, higher storeys `upper_wall`, tops and
  undersides `floor`, one row per cell face, a row shorter than the cell
  stretched up the face. The starter template has no block types, kits or trim
  sheets, and it is 2D, so a 3D level needs hidden setup
  (`docs/manual/guides/block-layers.md:16-30`). The Inspector gives a block
  type a material (D258); Create → Material opens the **New material**
  dialog (Layered surface, Standard, Decal, Foliage, Water, Unlit, Atlas
  surface).
- **Giving a block type a model is MCP-only.** Looks, boxes, rotations and
  metadata are JSON fields the editor renders read-only
  (`session/descriptor-fields.ts:118-120`). Opening models
  (`opening.model`), segment overrides, repeat models, profiles and raw
  elements have no UI either.
- **Rooms** are the last of 20 tools in the block toolbar
  (`BlocksPanel.tsx:467`, 913 lines). There are two wall systems with no explanation:
  edge pieces painted on the layer, and walls generated by Rooms.
- **Trim sheets as implemented** (`project-model/src/trim-sheet.ts`):
  - defaults 1024², 256 px/m, 8 px padding, nine equal rows of 0.375 m;
  - every row tiles in u (4 m repeat);
  - since 35.3 the layered surface carries trim layers: `layerSheets` (a
    trim material per layer; the first sheet's rows feed the generator and
    the mip cap; sheets whose rows differ are a problem), so two sheets on
    one surface must share a row table — one spec layout makes that true;
  - a profile segment is stacked by `round(length / rowMetres)` and
    stretched to fit (`arch-sweep.ts:422-424`), so a 0.15 m baseboard on a
    0.375 m row is squashed 2.5×;
  - `layout.json` import maps layer names to slot ids literally;
  - the Texture Designer's sheet editor defaults to 2048², 512 px/m, 8 px
    gutters, 16 px alignment (its service's `normalize` still defaults
    alignment to 8); bands cost row + 2 gutters, so rows start 8 px into a
    16-aligned band;
  - there is no written spec (36.1 writes it).
- **Custom piece rules are undocumented:**
  - a piece node's own transform is kept (`pieces.ts:88-95`), so a piece
    away from the file origin draws offset;
  - there is no rule for UVing a segment-override model against the rows.

## 3. Items

Order: spec → trim heights → kit data → Basic Kit → kit editor → block
editor → template → manual → acceptance.

**E2E budget (D181, D253):** no new e2e file, and the phase **reduces**
e2e time (the 35 full gate took 36 min against a 15 min budget).
- Target: `block-editor.e2e.ts` + `block-layers.e2e.ts` 40.8 s of test
  time in the 35 full gate (13.3 + 27.5 s) → **≤ 28 s (−30 %)**, and the
  block files together (those two, `blocks`, `block-world-uv` on both
  renderers: 64.2 s) **≤ 52 s**, with the block editor's, kit editor's and
  template's steps inside them. Cut duplicate coverage (one paint, fill,
  stamp and replace path each, not every tool through the UI), move
  browser-free checks (command shapes, palettes, kit validation, sweep
  UVs) to vitest. 36.9 records the numbers.
- `block-editor.e2e.ts` and `block-layers.e2e.ts` are rewritten to drive
  the block editor instead of the Inspector panel.
- The kit editor's checks extend `editor-window.e2e.ts` or `blocks.e2e.ts`.
